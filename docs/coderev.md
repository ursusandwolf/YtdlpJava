## Исправленные находки

| Находка | Реализация | Регрессионная проверка |
|---|---|---|
| Таймаут не охватывал чтение stdout | `ProcessExecutor` читает вывод в virtual thread; один deadline охватывает процесс и чтение, при таймауте/прерывании выполняется принудительное завершение | Реальные дочерние Java-процессы: молчание, строка без переноса, ненулевой exit code, stdout/stderr, прерывание, дерево процессов |
| Терялся каталог плейлиста | Задачи передают `outputDir` через `ResultDispatcher` файловому обработчику | Реальный `VideoDownloadTask` и менеджер сохраняют два плейлиста в разные каталоги |
| Ошибки загрузок давали код 0 | Менеджер собирает ошибки и сводку, CLI продолжает остальные URL и возвращает 1 при любом сбое; пустой список тоже ошибка | Частичный провал плейлиста, единственная неуспешная загрузка, пустой список, продолжение следующего URL |
| Резервные субтитры не подходили парсеру | Все пять стратегий запрашивают только VTT; отсутствие совместимого файла даёт явную ошибку | Проверены аргументы всех стратегий, отказ при JSON3, выбор нужного языка и имени |
| Неверный интервал нарушал цикл | `AppConfig.validate()` проверяет интервал, тип, формат, качество и путь до создания адаптеров; задача скриншотов тоже проверяет интервал | Ошибочные CLI-аргументы не запускают инфраструктуру; нулевой и отрицательный интервал не вызывают загрузчик |
| Перемещение файла ломало следующий обработчик | Файловый обработчик копирует источник; dispatcher вызывает остальные обработчики даже после ошибки; задачи очищают временные файлы в finally | Следующий обработчик читает источник, отказ одного не мешает другому, источник удаляется задачей после сбоя |
| Telegram игнорировал отказ API | Проверка `SendResponse.isOk()`; отрицательный или отсутствующий ответ вызывает IOException | Mock-ответы: успех, 403 Forbidden, null; реальная отправка не выполняется |
| Коллизии уничтожали предыдущий файл | Имя атомарно резервируется через `CREATE_NEW`; добавляются суффиксы ` (1)`, ` (2)` | Разное содержимое при повторном имени, восемь параллельных сохранений на Windows |
| Жёсткий предел абзаца игнорировался | Сборщик применяет `paragraphHardLimit`; проверяет конфигурацию и не разрывает surrogate pair | Длинный текст без пунктуации, длинное слово, Unicode, несколько блоков и сохранность текста |
| Lucene Analyzer не закрывались | Фабрика владеет общим лениво созданным сервисом; CLI закрывает фабрику после всей партии URL, включая исключения | Успех, частичный сбой и ошибка сборки задачи; закрытый сервис нельзя повторно использовать |

Коды CLI: `0` — успех, `1` — ошибка обработки, `2` — неверные аргументы.
Прерывание не трактуется как обычный сбой элемента: дальнейшая обработка прекращается.
Контракт обработчика требует оставлять исходный файл доступным другим обработчикам.
При ошибке передачи частично созданная копия удаляется; ранее сохранённые результаты остаются.

## Оставшиеся ограничения и решения к выпуску

- Пакетирование пока создаёт обычный JAR без Main-Class и зависимостей:
  запуск через classpath описан в README; исполняемый JAR ещё не настроен.
- Telegram подключается программно; флагов настройки в CLI нет.
- Поддерживаются только VTT-субтитры; JSON3/SRV не конвертируются.
- Видеоселектор предпочитает 720p, но последний резервный `best` не гарантирует предел.
- Таймаут завершает дерево процессов, доступное через ProcessHandle; отдельно
  отделившиеся от родителя процессы не гарантированно доступны этому механизму.
- Жёсткий лимит относится к текстовым элементам сборщика, до Markdown-разметки.
- Задачи к выпуску и необязательные улучшения перечислены в
  [контексте проекта](PROJECT_CONTEXT.md). Реальные интеграции, лицензия,
  упаковка и версия релиза остаются открытыми вопросами.
