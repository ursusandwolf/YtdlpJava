================================================================================
АДЕКВАТНІСТЬ АРХІТЕКТУРИ
================================================================================
Тип: модульний моноліт CLI (Maven, Java 21).
Стиль: Hexagonal / Ports & Adapters (полегшений).

Плюси:
- cli → config → core/task → model(ports) ← infrastructure
- Задачі залежать від портів, не від yt-dlp напряму
- Composition Root: ApplicationFactory
- Зовнішні процеси ізольовані в ProcessExecutor

Мінуси / компроміси:
- Downloader = кілька портів в одному (практично для фабрики)
- subtitle + processor трохи перетинаються (історично)
- Немає DI-контейнера — для CLI це правильно (KISS)

Висновок: для CLI з 5 сценаріями архітектура ADEQUATE, не over-engineered.

ПОТОК ДАНИХ (один URL)
================================================================================
CLI args -> AppConfig.validate -> LoggingConfigurator -> preflight
  -> Factory -> YtdlManager.process(url)
       -> PlaylistProvider.getPlaylistUrls
       -> for each: VideoTask.execute
            -> DownloadWorkspace.download
            -> [optional] ContentProcessor
            -> ResultDispatcher -> FileResultHandler
            -> cleanup temp
  -> exit 0|1|2
